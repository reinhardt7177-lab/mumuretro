# 태양 절벽 · 1번 사암 돌산 제작 계획

기준: `cliff-options-v03.png`의 **1번**. 2026-09-24 사용자 선택.
목표는 언챠티드에서 느끼는 ‘벽을 읽고, 붙잡고, 옆으로 이동하고, 틈을 뛰어넘는 긴장감’이다. 해당 게임의 모델이나 애니메이션을 복제하지 않는다.

## 외형 기준

- 따뜻한 황토색 사암, 불규칙한 수평 지층, 마모된 모서리, 깊은 세로 균열.
- 아래가 넓고 위로 갈수록 물러나는 3단 절벽. 원뿔이나 원통, 공중 원판, 규칙적인 볼더링 돌 배열을 피한다.
- 밝은 마모 자국이 있는 틈은 손잡이, 초록 이끼가 덮인 넓은 윗면은 휴식 지점이다.
- 길은 암벽에서 자라난 선반으로 구성한다. 아래가 절벽 몸체와 이어져 보여야 한다.
- 캐릭터 키 1.5m 기준 정상 발판 11.3m, 거울 중심 13.3m. 거울은 신전 방향 가장자리로 옮겨 빛이 정상 암석에 막히지 않게 한다. 게임 카메라와 구면 지형에 맞춘 축소 모형이다.
- Blender 원본·렌더·Unity 자산을 v03으로 보존한다. 이전 시안은 삭제하지 않는다.

## 플레이 흐름과 난이도

| 구간 | 플레이 | 실패·회복 | 시각 단서 |
|---|---|---|---|
| 1. 아래 절벽 | E로 매달림, W로 두 번 올라감 | Q로 출발점 복귀 | 밝게 닳은 수평 균열 |
| 2. 옆걸음 | D로 두 번 옮겨 잡고 W로 도약 위치 진입 | 잘못된 방향은 이동하지 않음 | 오른쪽으로 이어진 가는 암석 턱 |
| 3. 갈라진 틈 | 오른쪽 위 방향을 누르고 Space를 0.35초 이상 준비한 뒤 놓음 | 방향·준비가 부족하면 미끄러져 출발점에서 재도전 | 건너편 손잡이, 화면 준비 상태 |
| 4. 첫 휴식대 | W로 올라 E로 몸을 끌어올림 | 여기부터 출발점으로 되돌아가지 않음 | 풀 덮인 넓은 발판 |
| 5. 좁은 선반 | 폭 약 0.9m의 경사진 돌길을 직접 걸음 | 중간 쉼터를 실제 밟아야 체크포인트 갱신 | 지층이 이어지는 자연 돌길 |
| 6. 정상 벽 | 끝에서 Space로 위쪽 손잡이, W·E로 정상 진입 | 놓치면 마지막으로 밟은 안전 선반으로 복귀 | 정상 풀과 태양 거울 |
| 7. 태양 거울 | E로 잡고 방향 조정, Space로 빛 발사 | 빗나가면 각도를 다시 조정 | 빛이 얼음에 닿는 반응 |

도약의 성공 방향은 절벽 기준 오른쪽 위다. 카메라를 돌려도 키 의미가 바뀌지 않는다. 준비를 오래 했다고 실패하지 않으며, 체력 감소·짧은 반응 시간 제한은 넣지 않는다. 난이도는 조작과 공간 관찰에서 만들고, 반복 실패에 대한 벌은 짧게 한다. 자동 안내는 목적지를 알려 주되 캐릭터를 자동으로 이동시키지 않는다.

## 조작과 상태

- 이동/카메라는 기존 조작 유지. 매달린 상태만 절벽 조작으로 전환한다.
- W 위, A/D 옆, 방향 + Space 길게 눌렀다 놓기 도약, E 올라서기, Q 놓기.
- 수첩이나 다른 화면을 열면 도약 준비를 취소한다. 화면을 닫는 순간 의도하지 않은 점프가 나가면 안 된다.
- 이동 중 중복 입력 금지. 성공 도약과 실패 낙하 모두 중간 움직임이 보이도록 한다.
- 체크포인트는 첫 선반과 중간 쉼터. 위쪽 손잡이에서 놓았다고 아직 방문하지 않은 끝 선반으로 순간 이동하면 안 된다.
- 정상/첫 선반 방문은 이번 탐사 중 유지한다. 얼음 해제 기록만 기존 로컬 저장에 남긴다.

## 구현 구성

### 제작 좌표표

돌산 밑 기준, X는 좌우·Y는 높이·Z는 절벽 뒤쪽(미터). Blender 내보내기 파일의 `anchors`가 Unity 배치의 원본이다.

| 지점 | X | Y | Z | 역할 |
|---|---:|---:|---:|---|
| G0 | -5.20 | 0 | -5.40 | 출발 |
| H0 → H2 | -4.90 → -4.10 | 1.65 → 3.48 | -4.72 → -4.45 | 첫 수직 등반 |
| H3 → H4 | -3.05 → -1.85 | 3.65 → 3.68 | -4.65 → -4.75 | 수평 이동 |
| H5 → H6 | -1.28 → 0.35 | 4.42 → 4.82 | -4.60 → -4.45 | 약 1.69m 도약 |
| H7 | 1.45 | 5.45 | -4.00 | 올라서기 |
| P0 | 1.80 | 5.60 | -3.50 | 첫 체크포인트 |
| P1 | 3.00 | 6.10 | -2.20 | 좁은 길 |
| P2 | 4.00 | 6.80 | 0 | 중간 체크포인트 |
| P3 | 2.60 | 7.60 | 2.00 | 방향 꺾임 |
| P4 | 1.00 | 8.60 | 3.50 | 위쪽 벽 도약대 |
| H8 → H9 | 0.40 → 0.20 | 10.10 → 10.90 | 4.00 → 4.20 | 마지막 등반 |
| P5 | 0.10 | 11.30 | 5.00 | 정상 |
| 거울 | 1.35 | 13.30 | 5.20 | 태양 조준 |

1. Blender: 사암층, 균열, 통합 선반, 이끼와 제한된 풀을 제작한다. 재현 가능한 스크립트와 편집 가능한 `.blend`를 남긴다.
2. 모델의 손잡이·발판 좌표를 JSON에 함께 내보내 Unity에서 같은 좌표를 읽는다.
3. 기존 `MountainClimbController`를 확장한다. `PlanetExplorer`의 일반 이동과 점프를 교체하지 않는다.
4. 기존 `WaterMountainTrial`의 거울/얼음/저장을 유지한다. 기존 독립 얼음 신전이 중복 생성되지 않게 처리한다.
5. Unity Editor 생성기로 장면에 통합한다. 바위 충돌, 걸을 수 있는 표면, 카메라를 따로 검사한다.

## 제작 예산과 검증

- 돌산은 정적 메시를 재질별로 묶고 8개 이하 재질, 4만 삼각형 이하를 목표로 한다. 잔디 대량 배치나 새 고비용 셰이더는 사용하지 않는다.
- Windows 실행판에서 정상 등반, 잘못된 방향, 짧은 도약, 실패 후 재시도, 중복 입력, 체크포인트, 정상 거울과 얼음 해제를 검사한다.
- 일반 이동 회귀 검사도 실행한다. 결과 JSON과 실제 실행판 화면을 확인한다.
- Blender 렌더와 실제 게임 화면은 구분해서 보고한다. 컨셉 이미지와 픽셀 단위로 동일하거나 AAA 모션 품질이라고 주장하지 않는다.
- 이번 범위는 **외부 접근 절벽과 신전 입구 해제**다. 물의 신전 내부 퍼즐, 전신 접촉 IK, 무너지는 절벽, 패드/모바일 조작, 온라인 협동은 별도 단계다.

## 수용 기준

밑에서 정상 거울이 보이고, 선반이 바위에 붙어 있으며, 초록 휴식면과 손잡이가 구별되어야 한다. 방향 없는 Space 한 번으로 틈을 건너면 안 된다. 실패 뒤 조작이 잠기거나 진행을 건너뛰면 안 된다. 첫 시도 예상 3~5분은 설계 목표이며 학생 플레이테스트로 확인해야 한다.
