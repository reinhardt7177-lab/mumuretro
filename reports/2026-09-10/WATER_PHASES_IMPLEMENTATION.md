# 물의 신전: 상태 변화 퍼즐 1차 적용

## 적용 범위

기존 건축과 회랑을 유지하면서 세 방의 실제 퍼즐과 마지막 제단을 교체했다. 이번 작업은 플레이 가능한 첫 구현이며 새로운 Blender 신전 모델 제작은 포함하지 않는다.

| 방 | 조작과 실제 결과 |
|---|---|
| 1 | 가열 방향을 얼음 마개로 설정 → 마개가 서서히 녹음 → 도랑으로 물이 흐름 → 도랑 냉각 → 얼음 다리 생성 → 건너서 통과 |
| 2 | 용기 가열 → 위쪽 관으로 이동 → 집수판 냉각 → 물방울 발생 → 집수판을 물받이 위로 이동 → 수위와 부표 상승 → 문 열림 |
| 3 | 높은 수조의 얼음 마개를 녹여 상부 도랑에 공급 → 냉각해 회랑 연결 다리 생성 → 양쪽 회랑에서 집수판 냉각·위치 설정 → 아래에서 용기 가열 → 성소 수조를 채워 문 열기 |
| 마지막 | 제단에서 성소 깨우기 → 변화 과정의 짧은 연출 → 기존 지혜의 구슬·신의 대사·귀환 동선으로 연결 |

숫자 온도와 원하는 상태를 골라 밸브에 제출하던 규칙, 중앙 직진으로 끝나던 미끄럼 코스를 사용하지 않는다. 시간 제한을 줄이는 방식으로 난이도를 올리지 않았다.

## 동작 규칙

- 버튼은 장치의 작동·방향을 바꾼다. 정답 처리 자체는 시간에 따른 물의 변화와 도착 결과가 판단한다.
- 빈 도랑은 냉각해도 얼지 않는다. 첫 방에서 도랑을 가열하면 얼음이 다시 녹는다.
- 가열만으로 목적지 수조가 차지 않는다. 집수판 냉각과 물받이 정렬이 함께 필요하다.
- 잘못 떨어진 물방울은 회수받이로 돌아가므로 물 고갈로 진행이 막히지 않는다.
- 세 번째 방은 먼저 다리 복구를 달성해야 최종 수조를 채울 수 있다. 양쪽 비탈길은 복구용 안전 동선으로 남긴다.
- 장치 앞 명패와 상호작용 문구에 현재 동작, 물 부족, 냉각 부족, 빗나간 물방울, 수조 진행률을 표시한다.
- 물의 이동과 상태 변화는 게임용 진행도 모델이다. 정밀 열역학·유체 시뮬레이션이나 물의 양을 정량적으로 측정하는 실험은 아니다. 가열 용기 주변의 흰 김 표현은 응결된 작은 물방울이며 수증기 자체가 보이는 것은 아니다.

## 저장

물 신전 저장 형식은 v2다. 마개·물·얼음·수조의 진행도와 장치 설정을 저장한다. 재접속 시 해당 미완료 방 앞의 안전 지점으로 돌아오며 장치 진행은 유지한다.

v1 이관 시:

- 완료한 방, 신전 완료·구슬 획득 기록을 유지한다.
- 셋째 방에서 채운 밸브가 있으면 다리 복구로 인정하고, 두 개 이상 채웠으면 최종 수조 50%도 인정한다.
- 다른 퍼즐에 대응하지 않는 미완료 첫 방의 일시적인 얼음 타이머와 마지막 신의 1~2회 정답은 새 장치 설정으로 변환하지 않는다. 원본 v1 기록 전체는 v2의 `legacyWater` 필드에 보존한다.
- 새 저장과 이관 기록을 모두 검증한 뒤 적용하며, 손상된 기록으로 정상 상태를 부분 덮어쓰지 않는다.

## 검증

- `node tools/check-water-court.cjs`: 현재 통합 검사 진입점.
- `check-water-phases.cjs`: 잘못된 장치 조합의 진행 차단, 실제 이동으로 세 방·위층 다리·마지막 제단 통과, 중간 저장 복원, 손상 입력의 원자적 거절, v1 부분·완료 기록 이관.
- `check-water-phases-mobile.cjs`: 모바일 실제 상호작용 버튼 탭, 녹는 도중 저장, 전체 게임 새로고침 후 복원.
- 구버전 전용 테스트는 `check-water-court-v1.cjs`에 보존했다. 이 파일은 예전 퍼즐의 코드 버전에만 해당한다.
- 증거 화면과 JSON: `evidence/water-phases/`.

남은 미술 단계는 장치 형태와 연결관을 신전 분위기에 맞게 정교하게 만들고, 큰 설명판의 비중을 더 줄이는 것이다. 실제 사용자가 처음 보았을 때 이해하는지와 재미는 플레이 피드백으로 확인해야 한다.
