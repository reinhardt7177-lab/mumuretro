# 방향 전환 후 슬라이딩 조사

## 재현과 원인

Unity 6000.0.84f1의 기존 탐험 장면에서 대기 → 걷기 → 방향 전환 → 3초 정지 → 재출발 → 달리기를 연속 실행했다. `unity-sliding/before.json`에 수정 전 관절·Animator 측정값을 보존했다.

- 이동 속도와 Animator의 Speed는 3.2로 유지되었지만, 정지 후 재출발한 구간에서 다리 회전 변화가 0이 되었다.
- 같은 시점의 Animator 정규화 시간은 약 1,310억까지 커졌다. 걷기·달리기 클립 모두 반복 설정은 켜져 있었다.
- 대기 FBX의 시작·끝 프레임이 모두 0이고 실제 애니메이션 곡선도 없었다. 클립의 `length` 조회는 1을 반환했지만, 감속하며 대기 동작으로 섞이는 구간에서 실제 시간 계산이 폭증했다. 메타데이터의 종료 시간을 1초로 지정하는 것만으로는 해결되지 않았다.
- 이전 검사는 짧게 재생했을 때 메시가 변하는지만 확인해서, 정지·재출발 이후 동작 멈춤을 검출하지 못했다.

## 수정

원본 FBX는 유지한다. 에디터에서 원본 모델의 기본 관절 위치·회전·크기를 읽어 0초와 1초에 동일한 값으로 기록한 `NavigatorIdle.anim`을 생성하고, 기존 이동 BlendTree의 대기 항목만 교체한다. 장면을 다시 생성할 때도 동일한 수정이 적용된다. 이동 속도를 강제로 바꾸거나 매 프레임 애니메이션을 처음으로 되돌리지 않는다.

## 검증 범위

Windows 실행판 검사에 24초 분량의 대기·걷기·90도 전환·정지·반대 방향 재출발·달리기·재정지·재출발을 추가했다. 각 이동 구간에서 재생 시간, 이동 속도, 후반부 다리 회전 범위를 검증한다. 수정 전후 에디터 측정은 같은 입력 순서로 비교한다.

실제 결과와 화면은 `unity-sliding/`에 저장한다. 실행판 검증 결과는 완료 후 아래에 기록한다.

### 에디터 재현 비교

| 같은 입력 시점 | 수정 전 재생 시간 | 수정 후 재생 시간 | 수정 전 다리 회전 변화 | 수정 후 다리 회전 변화 |
|---|---:|---:|---:|---:|
| 정지 후 재출발, 780프레임 | 131,030,179,840 | 13.02 | 0° | 50.80° |
| 달리기 전환, 960프레임 | 131,031,654,400 | 16.55 | 0° | 73.13° |
| 다음 방향 전환, 1140프레임 | 131,033,128,960 | 20.79 | 0° | 35.42° |

다리 회전 변화는 앞선 15프레임 표본과의 왼쪽 허벅지 로컬 회전 차이다. 수정 후 전체 재현 검사에서 `LOCOMOTION_AUDIT_PASS`를 확인했다. 이 검사가 실패하면 실행판 빌드를 시작하지 않도록 했다.

### Windows 실행판 결과

- 빌드 성공, `result.json`의 `passed: true`, **54개 검사 통과**.
- 8개 연속 구간을 확인했다. 모든 이동 구간의 후반 다리 회전 범위는 약 34~63도로 유지되었고, 마지막 재출발 후 재생 시간은 27.42였다.
- 정지 후 반대 방향 재출발의 `turn-walk-a.png`, `turn-walk-b.png`에서 다리 자세가 달라지는 것을 직접 확인했다. `idle-front.png`의 팔 자세도 유지되었다.
- 점프 높이·착지, 능선 5개 지점 이동과 달리기 메시 변형 검사도 통과했다. 검사 로그에 실행 예외는 없었다.
- 이 결과는 현재 Windows 탐험 장면의 재현 시나리오에 해당한다. 게임 전체 이식이나 모든 상황의 애니메이션 품질 완성을 의미하지 않는다.
