# Unity 항해사 팔 자세 수정

## 확인된 원인

원본 스킨의 뼈대 연결이 끊어진 문제가 아니라, Unity 이식 중 추가한 `NavigatorPose`의 목표 좌표가 문제였다. 보정 전후를 같은 장면에서 비교했다.

- 왼쪽 어깨 높이 약 0.953, 보정 목표 팔꿈치 높이 0.91이었다. 어깨와 높이 차이가 거의 없어 팔이 옆으로 들렸다.
- 원본 대기 클립에서는 팔꿈치가 약 0.820 높이에 있었다. 잘못된 보정 후에는 약 0.908로 올라갔다.
- 걷기·달리기 원본 클립의 뼈대는 정상적으로 다른 자세를 만들었다. 원본 FBX와 스킨 웨이트를 다시 만들 필요는 없었다.
- 종전 검사는 뼈대 존재와 메시 변형만 확인했으며, 자연스러운 대기 자세는 확인하지 못했다.

## 변경

- 고정된 목표 높이를 없애고, 각 관절에서 뻗는 방향과 실제 팔다리 길이로 자세를 계산한다.
- 대기 중 팔은 몸 옆으로 내려오고 손은 팔꿈치 아래에 놓인다.
- 점프는 허벅지·무릎의 굽힘 각도로 구성한다. 손을 높은 절대 좌표로 끌어올리지 않는다.
- 스킨을 측정할 때 `BakeMesh(mesh, true)`를 사용해 스케일을 보정한다. 캐릭터 크기와 발 접지는 같은 방식으로 측정한다. [Unity 6 API 문서](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/SkinnedMeshRenderer.BakeMesh.html).
- 캐릭터 크기는 실제 평가된 스킨 높이 1.5를 기준으로 정규화한다. 기존 자연물 배치와 퍼즐 코드는 변경하지 않는다.

## 재발 검사

- 대기 시 위팔과 아래 방향의 각도 25도 미만.
- 손이 팔꿈치보다 최소 0.13 아래에 위치.
- 보정 100회 반복 후 손 위치 누적 오차 0.001 미만.
- 평가된 스킨 높이 1.5 ± 0.03, 발과 지면 오차 0.025 미만.
- 점프 무릎 굽힘 30~100도.
- 기존 능선 이동·점프 착지·Animator 검사를 함께 실행.
- 정면·측면 대기 화면과 점프 측면 화면을 확인.

증거는 `unity-rig/`의 `audit.json`, `result.json`, 실행 로그와 PNG에 저장한다. 사용자가 제보한 화면은 `reported-before.png`로 보존했다.

교정 후 에디터 관절 측정에서 왼쪽 위팔은 아래 방향과 **9.13도**, 팔꿈치는 어깨보다 **0.204 아래**에 있다. 평가된 스킨 높이는 **1.499996**, 발의 지면 오차는 **0.000003**이었다. 최종 실행판 결과는 별도의 `result.json`과 화면으로 확인한다.

## 실행판 검증 결과

- Unity 6000.0.84f1 Windows 빌드 성공. `unity/check.ps1` 실행 결과 `passed: true`, **34개 검사 통과**.
- 점프 최대 높이 약 0.950, 원래 지면으로 착지, 능선 5개 지점 이동 및 달리기 스킨 변형 확인.
- `idle-front.png`, `idle-side.png`에서 양팔이 몸 옆으로 내려오고 발이 지면에 닿는 것을 직접 확인했다. `jump-side.png`에서 팔꿈치와 무릎이 구부러지는 자세를 확인했다.
- 이번 검증은 현재 Unity 탐험 장면의 자세·이동 범위다. 전체 웹 게임 이식이나 모든 애니메이션 전환의 품질 완성을 뜻하지 않는다.
