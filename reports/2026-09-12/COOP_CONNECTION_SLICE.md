# 3인 협동 접속 시험 구현

## 현재 사용

로컬 정적 게임 서버(5512)와 `node server/coop.cjs`(5520)를 실행한다. 게임 설정에서 ‘친구와 함께 · 접속 시험’의 방 만들기를 누르고 다른 브라우저에서 코드를 입력한다. 최대 3명. 상대는 범선/행성에서 청록색 위치 표식으로 표시된다. 아직 정식 캐릭터 애니메이션 복제가 아니다.

개인 세이브는 기존 로컬 저장 그대로다. Supabase 인증과 개인 클라우드 저장은 사용하지 않는다. 실시간 서버는 메모리 방과 임시 토큰만 유지하며 재시작하면 방은 사라진다. 30초간 응답 없는 접속은 다음 요청 시 정리한다.

## 검증

서버 HTTP 테스트: 생성, 3명 입장, 네 번째 거부, 토큰 비노출, 잘못된 토큰 거부, 잘못된 위치 거부, 퇴장 후 입장, 연결 만료 통과.

## 아직 남은 필수 작업

- 균형 신전 상자 소유권/배치/문을 서버가 판정하도록 연결. 현재 퍼즐은 공유되지 않음.
- 캐릭터 외형/방향/애니메이션 및 위치 보간. 현재 위치표식이며 지연이 보일 수 있음.
- 재연결/호스트/장면 진입 및 보상 처리 규칙.
- 배포용 서버, HTTPS, 요청 속도 제한, 로그/운영 설정. 현재 127.0.0.1에만 바인딩되며 다른 학생의 PC나 배포 사이트에서 이용 불가.
- IP/세션별 방 생성 제한 및 이동의 서버 검증. 현재 Origin 제한은 인증 대체가 아님. 공개 배포 전 필요.

개발 진행을 정식 협동 플레이 완료로 해석하지 않는다. 공개 사이트에서는 서버 준비 중으로 안내하며 로컬 서버로 연결을 시도하지 않는다.

## 균형 퍼즐 서버 로직 추가

server/balance.cjs가 세 단계의 상자 배치, 소유권, 선택 개수, 지지대와 완료 판정을 소유한다. 클라이언트는 pick/place/drop/count/pivot 명령만 전송한다. /balance HTTP API 추가. 정상적인 순서로 앞 단계를 완료해야 다음 단계 명령 허용. 개인 토큰은 공유 상태에 포함하지 않는다. 퇴장/만료 시 들던 상자는 원위치 반납.

단위 검사와 실제 두 HTTP 클라이언트 검사 통과: 중복 집기 거부, 다른 사람 상자 놓기 거부, 순차 개방, 세 퍼즐 정답, 퇴장 반납, 완료 상태 공유.

src/core/CoopBalance.js는 게임 장치 바인딩 초안이며 아직 UI에서 호출하지 않는다. 실제 신전 공유가 완성된 상태는 아니다. 연동 전에 협동 전용 방/고정 시드, 개인 저장 분리, 상대가 든 상자 표시, 멱등 명령 ID, 네트워크 유실 복구, 위치/상호작용 거리 검증이 필요하다. 현재 HTTP 상태 판정은 좌표상 실제 접근까지 검사하지 않아 공개 배포하지 않는다. 서버 프로세스 재시작도 필요.
