# 마지막 그림자 신전 구현 보고서

2026-09-08 · 로컬 적용 완료 · 공개 사이트 미배포

**방향과 높이를 함께 조절하는 마지막 그림자 신전을 개편했다.** 그림자 사당의 일반 관문 세 곳과 마지막 신전까지 네 공간에 같은 미술 기준을 적용했다. 이번 보고서는 마지막 신전의 실제 화면, 광학 판정, 보행, 저장 복원과 회귀 검사 결과를 다룬다.

## 플레이에서 달라진 점

| 요소 | 적용한 동작과 표현 |
|---|---|
| 공간 | 짙은 밤하늘 아래 밝은 석재 아치와 원형 그림자 바닥을 배치했다. 중앙 수호상, 등불, 두 손잡이가 같은 공간에서 보인다. |
| 방향 손잡이 | 왼쪽의 여덟 살 바퀴를 E로 돌리면 등불이 수호상 둘레의 여덟 자리로 이동한다. 바퀴의 밝은 표시는 실제 등불 방향과 일치한다. |
| 높이 손잡이 | 오른쪽의 세 눈금 손잡이를 E로 움직이면 등불 높이가 바뀐다. 손잡이의 가로대도 해당 눈금으로 움직인다. |
| 그림자 | 수호상의 몸·팔·머리·거울 등 실제 부품을 등불 위치에서 바닥으로 투영한다. 등불이 높아질수록 그림자가 짧아진다. |
| 목표 | 사각형 대신 수호상 그림자의 바깥 윤곽을 바닥에 새겼다. 방향과 높이를 모두 맞춰 윤곽에 그림자를 포갠다. |
| 완료 | 목표 선이 밝아지고 수호상이 눈을 뜨며 구슬이 내려온다. 구슬은 가까이 가서 한 번만 얻는다. |
| PC·모바일 | 같은 가까운 장치 상호작용을 사용한다. 모바일 안내는 ‘등불 회전’, ‘등불 높이’와 단계 숫자로 간결하게 표시한다. |

방향만 맞추거나 높이만 맞추면 완료되지 않는다. 정답을 알려 주는 화살표는 추가하지 않았다. 눈을 뜨는 1.5초 연출과 구슬이 내려오는 1.4초 연출은 해결 직후 함께 진행한다. 수첩을 열면 둘 다 멈춘다.

## 레퍼런스와 실제 화면 비교

[빛과 그림자 레퍼런스](SHADOW_REFERENCE.md)의 네 번째 장면에서 **돌 수호상·바닥 표적·서로 다른 두 손잡이·푸른 밤과 황동 장치**를 가져왔다. 실제 광원 높이와 공간 치수는 이미지의 인상보다 보행과 투영 결과를 기준으로 정했다.

방은 22×16u, 등불의 회전 반경은 5u다. 수호상 높이는 약 2.29u이고 등불 높이는 4.16·5.33·6.825u다. 모든 등불이 수호상보다 높으므로 바닥 투영이 끊기거나 뒤집히지 않는다. 원형 바닥 안쪽은 균일한 색으로 그려 장식 조명의 얼룩이 퍼즐 그림자로 보이지 않게 했다.

신전에 들어가면 카메라가 바라보는 높이가 부드럽게 올라간다. PC 입구 기본 시점에서 등불은 방향·높이 24조합 모두 화면 안에 들어온다. 아래 비교 캡처는 카메라 변경 효과를 분리하기 위해 **개편 전과 같은 입구 위치·시점·문제 씨앗·손잡이 상태·1440×900 해상도**로 찍었다. 보고서 첫 이미지는 개편한 카메라로 조금 더 걸어 들어간 실제 화면이다.

![개편 전 같은 입구 시점](D:/mumumetro/reports/2026-09-08/evidence/shadow-sanctum/before.png)

![개편 후 같은 입구 시점](D:/mumumetro/reports/2026-09-08/evidence/shadow-sanctum/after-comparison.png)

현재는 단순한 입체 도형으로 만든 수호상과 반복 석재 구조다. 레퍼런스의 정교한 조각, 석재 표면, 풍부한 원경까지 구현한 것은 아니다. 모바일 세로 화면은 한 손잡이를 가까이서 조작하는 데 맞으며, 등불과 반대편 목표를 함께 살피려면 시점을 돌려야 한다. 실제 휴대전화 성능과 사용자 길 찾기·학습 효과는 아직 측정하지 않았다.

## 그림자와 판정의 일치

기존 신전은 등불 높이로 길이를 정한 사각형을 그림자로 표시했다. 개편 전 실제 브라우저에서 **원기둥 형상의 받침대와 몸통만** 광선으로 조사해도, 9개 상태의 23,913개 바닥 표본 중 2,848개가 표시 그림자와 달랐다. 약 11.9%이며, 머리·거울까지 포함한 옛 석상 전체의 오차율로 해석해서는 안 된다.

새 신전은 부품의 실제 꼭짓점을 점광원에서 바닥으로 투영하고 부품별 그림자를 합친다. 광원 높이를 H, 꼭짓점 높이를 y라고 할 때 수평 거리는 H/(H−y) 배로 늘어난다. 목표 선에는 겹친 부품 내부의 선을 없애고 바깥 윤곽만 남긴다.

검사에서는 **방향 8개 × 높이 3개, 총 24상태의 55,296개 바닥 표본**을 조사했다. 등불에서 바닥으로 향하는 광선의 실제 수호상 충돌, 표시 메시의 삼각형, 계산된 그림자가 모두 일치했다. 표본상의 불일치는 0개였다. 24상태는 모두 구별되는 그림자를 만들었고 정답은 하나였다. 여덟 방향 모두 높이를 올리면 길이가 줄었다.

이 검사가 실제 고장을 찾는지도 확인했다. 별도 브라우저에만 그림자 메시를 0.8u 옆으로 옮기는 오류를 주입하자 표시와 실제 광학 결과의 불일치를 검출했다. 게임 원본에는 이 오류를 적용하지 않았다.

## 저장과 보상 이어하기

개편 전에 실제 게임에서 저장한 중간 기록과, 수호상이 깨어나며 구슬이 내려오던 기록을 보존해 새 코드로 불러왔다.

- 무작위 씨앗과 목표, 손잡이 방향·높이, 앞의 열린 관문 세 곳, 힌트 진행을 유지한다.
- 수호상의 각성 정도와 구슬의 내려오는 위치를 복원해 이어서 진행한다.
- 새 저장은 장치 의미를 기록하는 버전 2 형식을 사용한다. 기존 메시 구조를 기록하던 저장도 검증한 뒤 읽는다.
- 새 배치에서는 수호상이 방 중앙으로 옮겨졌다. 옛 기록의 재개 위치가 마지막 신전 안이면 입구 안전 지점으로 옮기며, 퍼즐 진행과 바라보던 방향은 유지한다.
- 구슬 위치는 옛 배치와 같게 유지했다. 이미 얻은 구슬이나 완료 여부만 있는 오래된 기록은 보상을 중복 지급하지 않는다.
- 범위를 벗어난 높이 또는 실제 방향·높이와 모순되는 완료 값은 살아 있는 방을 바꾸기 전에 거부한다.

## 렌더 비용과 수정 과정

같은 비교 화면에서 후처리까지 전체 렌더 패스를 합산했다.

| 측정 항목 | 개편 전 | 개편 후 |
|---|---:|---:|
| 그리기 호출 | 337 | 332 |
| 삼각형 | 7,919 | 14,155 |
| 점 | 640 | 640 |

반복 석재를 묶어 호출은 약 1.5% 줄었지만, 구조물과 실제 윤곽을 추가해 삼각형은 약 79% 늘었다. 이 수치만으로 프레임 속도가 좋아졌다고 주장하지 않는다.

초기에는 등불이 PC 화면 위로 벗어나는 조합이 있었다. 수호상과 등불의 수직 치수를 같은 비율로 낮춰 바닥 투영을 유지하고, 신전 카메라의 바라보는 높이를 조정했다. 중간 값에서도 가장 높은 등불 한 조합이 화면을 벗어나 최종 값에서 24조합을 다시 확인했다.

수호상 어깨 장식과 몸통 끝면이 겹쳐 줄무늬처럼 보이는 현상은 장식 높이를 띄워 고쳤다. 방향 바퀴의 표시가 실제 등불보다 90도 돌아간 문제도 표시의 초기 위치를 수정했다. 마지막 모바일 캡처에서는 긴 조작 안내가 단어 중간에서 끊겨 짧은 장치명으로 정리했다.

저장 회귀 도구는 예전 메시 저장 구조만 가정하고 있어 새 형식에서 검사 자체가 중단됐다. 새 형식에서는 높이를 잘못된 값으로 바꾸도록 고쳐 손상 기록의 원자적 거부 검사를 유지했다. 재접속 후 첫 구슬 줍기 입력을 입장 안내가 먼저 받던 검사 준비 오류도 안내 초기화 뒤 조작하도록 바로잡았다. 이를 실제 보상 유실로 기록하지 않는다.

## 코드와 근거

공간 수치와 색은 `src/data/shadowSanctum.js`, `src/data/lighting.js`에, 구조물은 `src/shrine/ShadowSanctum.js`에 분리했다. 광학·외곽선·신전 저장 형식은 `src/shrine/SanctumOptics.js`가 담당한다. 기존 방 생성과 진행 복원, 카메라에 필요한 연결만 추가했다.
