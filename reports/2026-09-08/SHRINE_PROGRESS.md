# 여섯 사당 중간 저장 확장

2026-09-08 · 로컬 구현 결과

물 사당에만 있던 중간 저장을 나머지 다섯 사당에 확장했다. 사당을 나갔다 오거나 브라우저를 다시 열어도 풀던 장치와 물건을 이어서 사용할 수 있다. 이번 작업은 저장과 플레이 오류 수정이며, 다른 다섯 사당의 대규모 그래픽 개편은 다음 작업이다.

## 저장하는 것

| 사당 | 복원 범위 |
|---|---|
| 무게 | 상자의 무게·크기·원래 자리, 접시·받침·손의 소유 관계, 압력판 주문과 라운드, 양팔저울 배치·기울기 |
| 그림자 | 등불 시간, 거울 배치·방향, 그림자 크기 문제 순서·현재 물체 위치·잡은 상태, 신전의 방향·높이 |
| 분리 | 체와 주문 순서, 남은 혼합물·장착한 체, 자석 분류 기준·통·물통 검사·손의 물건, 증발 단계, 신전 혼합물의 처리 순서 |
| 화산 | 보호 기둥 배치와 진동 단계, 가라앉은 발판·현재 칸, 간헐천 주기, 신전 수로의 회전·진행 |
| 지층 | 시추 코어와 화석 순서, 꽂은 화석·손의 화석, 낙석 상태, 다섯 색 손잡이, 제단 구슬·눈뜨는 연출 |
| 물 | 기존 얼음·구멍·온도·밸브·다리·신전 저장 계약을 유지 |

공통으로 열린 문, 힌트 단계와 누적 시간, 첫 입장 난이도, 보상 획득 여부, 안전한 재시작 위치를 남긴다. 여러 사당의 미완료 기록을 함께 저장하며, 다른 사당에 있는 동안에는 기존 사당의 시간이 흐르지 않는다.

## 재접속 위치

- 일반 퍼즐은 서 있던 지상 위치로 돌아온다. 들고 있던 물건도 계속 사용할 수 있다.
- 그림자·지진·간헐천·낙석 구간에서는 해당 구간의 안전한 입구에서 이어간다. 장치 배치와 시간은 보존한다.
- 용암 발판은 현재 밟은 온전한 칸의 가운데로 돌아온다. 지나온 발판이 가라앉은 기록도 유지한다. 이미 떨어지는 상태면 해당 발판 구간만 다시 준비한다.
- 물 사당의 임시 얼음·미끄럼 구간은 기존 안전 발판 규칙을 유지한다.
- 이미 통과한 관문은 되돌아가도 실패로 입구에 보내지 않으며, 완료한 장치를 다시 조작해 진행과 문 상태를 어긋나게 만들지 않는다.

## 함께 수정한 오류

**분리 사당 신전의 화로 재사용.** 화로 하나가 소금물과 모래 섞인 소금물에 모두 필요한데, 첫 그릇에 놓으면 다시 쓸 수 없었다. 이전 검사는 도구를 직접 손에 넣어서 개별 순서만 검사했기 때문에 완주 불가를 잡지 못했다. 새 검사는 선반에서 집는 상호작용부터 수행했고 실패했다. 이제 분리가 끝난 그릇은 결과를 유지하고 도구를 선반에 돌려준다. 진행 중인 그릇에서는 마지막 도구를 되가져올 수 있다.

**압력판 목표 표시.** 유효한 주문은 한쪽에 최대 13을 요구할 수 있지만 표시 점은 9개뿐이었다. 최대 주문을 표시할 수 있도록 13개로 늘렸다. 저장 검증의 범위도 실제 주문 생성 규칙에 맞췄다.

**검사 후 상태 보존.** 내장 검사가 물 사당 이외의 진행 중인 방을 초기화할 수 있었다. 이제 방문한 모든 사당의 상태를 보존하고, 검사 중에만 만든 임시 방은 캐시에서 제외한다.

다섯 사당에서 첫 관문까지 실제 이동 입력으로 걸었고, 추·체·화석을 든 채 새 브라우저로 이어간 뒤 장치까지 걸어가 놓았다. 후반 라운드와 신전은 접근 조건을 준비한 뒤 실제 상호작용 메서드로 풀고, 단계마다 새로 만든 방에 저장을 복원했다. 후반까지 일반 조작만으로 걸어 완주한 검사는 아니다.

중복 소유, 다른 씨앗, 닫힌 문 너머 위치, 잘못된 구슬 상태, 순환하는 메시 부모 관계를 넣어도 살아 있는 장치를 부분 변경하지 않고 거부했다. 손에 든 물건의 복원을 일부러 제거했을 때 정상 복원 조건이 실패하는 것도 확인했다. 손상된 활성 사당은 원문을 백업하고 읽을 수 있는 다른 탐사 기록을 이어간다. 옛 버전에서 이미 완료한 사당은 다시 잠기거나 구슬을 중복 지급하지 않는다.

## 구현과 다음 개편 시 주의점

`Room.js`는 저장된 씨앗으로 무작위 배치를 재현한다. `DeviceProgress.js`는 허용한 상태만 읽으며, 물건의 연결은 고정 목록 번호로 저장한다. 장치의 시각 상태는 초기 상태와 달라진 부분만 남긴다. `ShrineProgress.js`는 모든 필드를 검증한 뒤 장치·문·힌트·보상을 함께 적용한다. 기존 물 사당 저장 필드는 그대로 유지했다.

향후 그래픽 개편에서 메시 구조를 바꾸면 저장 계약의 이관도 함께 작성해야 한다. 장치 배치 식별값이 다르면 옛 메시 번호를 새 물건에 무작정 적용하지 않는다. 현재는 호환되지 않는 기록을 원문 백업하고 복구 가능한 진행을 살리는 방식이다. 텍스트 알림의 남은 표시 시간과 순수 장식 회전까지 모두 동일하게 재현하는 기능은 아니다.

비교 기준은 먼저 구현한 [물 사당의 이어하기](WATER_COURT.md)다. 이번 확장으로 사당마다 다시 시작하는 범위가 달랐던 불편을 줄였으며, 위험 구간은 안전 위치와 진행 보존을 함께 적용했다. 실제 학생의 길 찾기 이해도, 학교 태블릿·Safari, 장시간 성능은 별도 사용성 검증이 필요하다.

다음 그래픽 작업은 기존 [레퍼런스 우선 원칙](VISUAL_REFERENCE.md)을 따른다. 빛과 그림자 사당부터 목표 이미지를 만들고, 사용자가 방향을 확인한 뒤 공간·재질·빛줄기·카메라를 구현하는 순서를 제안한다. 무게·분리·화산·지층도 각각의 주제로 이어가되, 현재 모든 사당의 그래픽 개편이 끝났다는 뜻은 아니다.
