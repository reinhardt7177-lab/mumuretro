# 그림자 사당 — 거울 회랑 구현 보고서

2026-09-08 · 로컬 적용 완료 · 레퍼런스의 첫 장면 구현

그림자 사당의 두 번째 관문 **거울 세 장**을 넓은 석조 회랑으로 바꿨다. 밤하늘 아래 아치, 밝은 돌과 황동 받침대, 옆을 향한 광원과 수신 장치를 만들었다. 플레이어가 거울을 돌리면 실제 면에서 빛이 꺾이고, 세 거울을 거쳐 표적에 닿으면 다음 문이 열린다.

## 실제 게임 화면

세 거울을 직접 조작해 문을 연 뒤 입구 쪽으로 걸어 돌아와 촬영했다. 생성 이미지가 아닌 게임의 브라우저 캡처다.

## 구현한 변화

| 항목 | 변경 내용 |
|---|---|
| 공간 | 9×14u → 18×14u. 방 길이와 다음 관문의 위치는 유지 |
| 건축 | 석조 아치와 낮은 돌담, 중앙이 열린 부분 원형 지붕, 줄눈이 있는 평평한 바닥 |
| 장치 | 회전 손잡이와 황동 프레임, 양면 거울, 옆을 향한 광원 렌즈, 불이 켜지는 수신기 |
| 반사 | 45°씩 회전. 계산된 거울 면의 교점에서 광선을 연결하고 방 경계에서 종료 |
| 접근 | 받침대와 몸이 겹치지 않도록 충돌 범위를 확보. 가장 가까운 거울 하나만 E로 조작 |
| 카메라 | 아치·돌담·거울·장치의 실제 표면 앞에서 멈춤. 벽 안 진입을 막고, 가까운 장치에 끼면 열린 지붕 쪽으로 올라가 탐험가와 손잡이가 보이게 조정 |
| 조명 | 거울방 안의 제한된 보조 조명과 황색 빛줄기. 다른 그림자 퍼즐에 새 그림자를 투사하지 않음 |

레퍼런스에서 정한 밤·밝은 석조·황동·열린 아치와 빛을 따라가는 구성을 실제 조작 가능한 공간으로 옮겼다. 광선의 진행 방향과 거울 표면을 함께 90° 회전해 기존 퍼즐의 해결 관계를 유지했다. 그림에 그려진 각도를 복사하지 않고 반사식으로 계산한다.

참고 이미지의 회화적 질감, 주변의 오래된 건물, 식생과 바닥 반사는 이번 구현 범위에 포함하지 않았다. 지금 화면은 단순한 입체 형태로 만든 첫 적용이며, 레퍼런스와 같은 최종 그래픽 수준이라고 평가하지 않는다. 인접한 방과 연결 통로에는 기존 미술이 남아 있다.

## 기존 저장 이관

개편 전에 실제 게임에서 만든 저장을 보존해 새 게임에서 읽었다. 기존 거울 각도, 완료한 앞 관문, 힌트와 씨앗이 유지됨을 확인했다. 예전 거울방 안에서 중단했다면 새 받침대에 끼지 않도록 거울방 입구에서 이어간다. 다른 방의 체크포인트와 퍼즐 기록은 이어진다.

새 거울 저장은 각도와 도달 여부를 담는 장치 버전 2다. 복원할 때 광선을 다시 계산하며, 잘못된 도달 값은 실제 진행을 바꾸기 전에 거부한다. 이전 장치의 시각 구조 검증도 유지해 오래된 저장을 무조건 허용하지 않는다. 거울방의 장식을 추가해도 새 저장은 메시 개수에 종속되지 않는다.

## 실행 검증

| 검사 | 결과 |
|---|---|
| 거울 회랑 전용 | 18개 통과 |
| 광학 조합 | 8개 씨앗 × 512가지 = 4,096개. 방 경계, 반사식, 연결점 검사 통과 |
| 퍼즐 성립 | 검사한 모든 씨앗에서 해결 가능. 초기 자동 완료 없음, 표적 도달에 세 거울 필요 |
| 실제 보행 | 연결 다리 → 세 거울 조작 → 열린 출구 → 다음 통로 통과 |
| 카메라 | 보행 가능한 6개 위치 × 3개 피치 × 8개 방향 = 144개. 실제 표면과 여유 거리 검사 |
| 저장 | 개편 전 저장 이관, 새 저장 재접속, 잘못된 완료 값 거부 |
| UI | PC 수첩 아이콘, 모바일 터치 E 한 번 회전, 모바일 수첩 열기 통과 |
| 고장 검출 | 광선 경계 제거와 옛 카메라 최소 거리 복원 시 각각 고장을 검출 |
| 사당 저장 회귀 | 기존 42개 통과. 내장 A~W 23그룹 실행 및 상태·저장소 보존 확인 |
| 물 회랑 회귀 | 기존 21개 통과. 보행·입체 다리·카메라·저장·터치 조작 확인 |
| 소스 | 85개 모듈, 228개 로컬 import, 19개 vendor 해시와 음악 경로 통과 |

첫 그림자 밟기 관문은 완료 상태로 준비했다. 거울방의 이동과 E 입력은 실제 게임 갱신 경로로 실행했으며, 테스트는 자동 조향을 사용한다. 전체 그림자 사당의 일반 사용자 완주나 길 찾기 이해도를 측정한 결과는 아니다. 모바일 검증은 Edge 에뮬레이션이며 실제 휴대전화의 프레임 속도를 보장하지 않는다.

측정 화면은 1440×900이다. 후처리를 포함한 전체 렌더는 **592회 호출, 18,065개 삼각형**이었다. 새 회랑은 199개 반복 조각을 11개 묶음으로 그린다. 이는 특정 화면의 렌더 부담 측정이다. 변경 전 `before.json`의 호출 수 1은 마지막 후처리 패스만 센 오류이므로 전후 성능 비교에서 제외했다.

## 검토 중 수정한 문제

- 처음 적용한 입구 기둥이 시야를 좁혀 중앙 개구부를 넓혔다.
- 방 배치 변환에서 건축 종류 필드가 빠져 기존 바닥 줄이 겹쳤다. 필드를 전달하고 바닥돌을 새 타일 아래로 내려 겹침을 없앴다.
- 초기 캡처 도구가 전환 섬광의 프레임까지 멈춰 화면이 흰색으로 덮였다. 게임 루프만 멈추고 UI 프레임은 정상 종료시켰다.
- 카메라 검사 위치 하나가 광원 받침대 안이었다. 검사를 실제 보행 가능한 위치로 바꾸고, 별도 고장 주입으로 가까운 돌담에서 기존 카메라 최소 거리의 문제를 확인해 수정했다. [중간 검사 기록](evidence/mirror-gallery/iteration-camera.json)
- 장치 충돌만 피하면 모바일 화면이 캐릭터의 뒤통수로 가려지는 경우가 있었다. 거울 회랑에서만 위쪽으로 돌아보도록 추가하고, 실제 모바일 캡처와 시점 거리 검사로 확인했다.
