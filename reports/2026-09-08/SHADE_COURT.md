# 그림자 밟기 회랑 구현 보고서

2026-09-08 · 로컬 적용 완료 · 빛과 그림자 레퍼런스의 두 번째 장면

그림자 사당의 첫 관문을 **움직이는 등불과 기둥 그림자를 따라 걷는 석조 회랑**으로 바꿨다. 기존 화면과 안전 판정이 서로 달랐던 문제를 수정했고, 달리기 없이 세 난이도에서 통과하는 것을 확인했다.

## 실제 게임 화면

관문을 통과하고 입구 쪽으로 걸어 돌아와 촬영했다. 생성 이미지가 아닌 게임 캡처다.

## 고친 문제

기존 그림자 메시와 안전 판정은 회전 방향과 띠의 폭이 달랐다. 개편 전 다섯 등불 위치에서 기둥 주변을 제외한 **6,965개 지점 중 1,000개, 약 14.4%**가 서로 다른 결과를 냈다. 어두운 바닥을 밟아도 들키거나, 밝은 곳인데 안전할 수 있었다.

이제 등불에서 기둥의 위·아래 꼭짓점을 바닥으로 투영해 그림자 다각형을 만든다. **화면에 그리는 삼각형과 발 위치의 안전 판정이 같은 다각형을 사용한다.** 실제 기둥 메시가 등불의 광선을 가리는지도 독립적으로 검사했다. 새 회랑의 9,590개 표본에서 화면·판정·기둥의 빛 가림이 모두 일치했다. 방 폭과 표본 간격이 달라 전후 표본 수는 서로 다르다.

바닥은 별도 조명의 그림자를 받지 않는다. 장식물이나 달빛이 또 다른 안전한 길처럼 보이는 일을 막고, 네 기둥의 투영만 규칙으로 읽히게 했다. 입구와 출구의 짙은 바닥은 계속 안전한 대기 공간이다.

## 공간과 플레이

| 항목 | 적용 결과 |
|---|---|
| 방 크기 | 9×16u → 14×16u. 길이와 다음 거울방의 위치 유지 |
| 기둥 | 높이 3.6u, 반경 0.76u, 16각 단면. 표면에 황동 띠와 어두운 밑부분 |
| 이동 등불 | 높이 4.8u, 가로 반경 5.4u·세로 반경 6.2u의 타원 궤도. 위쪽 레일에 매달린 형태 |
| 그늘 | 기둥의 실제 형태로 투영. 밝은 중앙 바닥 안에만 표시 |
| 안전 대기 공간 | 앞뒤 각각 2.2u. 출발 전 움직임을 관찰할 수 있음 |
| 노출 경고 | 빛에 머무르면 앞쪽 눈과 발밑 고리가 밝아짐. 그늘에서 노출량이 회복됨 |
| 실패 | 노출 한도를 넘으면 해당 방의 안전한 입구로 복귀 |
| 완료 후 | 다음 문이 열리고 돌아오는 길에서 경고가 꺼짐 |
| 카메라 | 기둥·아치·등불 장치의 실제 표면 앞에서 멈추고, 가까운 장애물은 위쪽으로 돌아봄 |

그림자가 움직이는 기존 규칙과 노출 유예는 이어간다. 시험한 난이도 0·3·5의 노출 한도는 각각 0.75·0.585·0.475초다. 빛에 잠깐 노출되었다고 즉시 실패하지 않는다. 판정은 플레이어의 바닥상 발 위치를 기준으로 한다.

[레퍼런스](SHADOW_REFERENCE.md)의 열린 아치, 남색 그늘, 밝은 석재와 황동 등불을 적용했다. 초기 구현에서는 등불과 기둥이 너무 높아 입구 화면에서 광원이 잘 보이지 않아 높이를 낮췄다. 회화적인 표면 질감·낡은 석재의 세부 표현은 다음 미술 보강 대상으로 남았다. 주변의 연결 통로와 뒤쪽 방에는 기존 미술이 남아 있다.

## 저장과 검증

개편 전에 실제로 저장한 등불 위상과 힌트가 새 회랑에서 복원된다. 새 장치 저장은 위상·노출량을 담는 버전 2이며, 그림자 메시를 그대로 저장하는 대신 복원 후 다시 계산한다. 위험 구간에서 중단했다면 앞쪽 안전한 위치에서 재개한다. 완료 여부도 복원해, 완료 후 재접속할 때 경고가 되살아나지 않는다.

| 검사 | 결과 |
|---|---|
| 회랑 전용 | 16개 통과 |
| 광학·화면 | 5개 위상 × 1,918개 지점 = 9,590개. 표시·안전·실제 기둥 충돌 불일치 0 |
| 실제 보행 | 난이도 0·3·5에서 입구부터 보통 속도로 이동해 완료. 실패·경로 이탈 0 |
| 경고·복구 | 밝은 곳의 경고, 실패 후 대기 공간 복귀, 저장 후 노출 회복 확인 |
| 재개·왕복 | 옛 저장 이관, 중간·완료 상태 재접속, 완료 후 왕복 확인 |
| 카메라·충돌 | 144개 시점 및 기둥 쪽으로 걷기 확인 |
| 고장 검출 | 표시 그림자만 1u 이동시킨 실행에서 불일치를 검출 |
| 모바일 | 수첩을 열면 등불 회전과 노출량이 멈춤 |
| 기존 사당 저장 | 42개 통과. 내장 A~W 23그룹 실행 및 상태·저장소 보존 확인 |
| 거울 회랑 회귀 | 기존 18개 통과 |
| 소스 | 88개 모듈, 234개 로컬 import, 19개 vendor 해시와 음악 경로 확인 |

보행 검사는 시작 난이도와 등불 위상을 준비한 뒤 실제 이동 입력과 게임 시간으로 실행한다. 달리기를 사용하지 않았고, 자동 조향 도구가 그늘과 노출 여유를 고려해 이동했다. 세 경우에서 회랑 진입 뒤 약 5.3~7.8초가 걸렸지만 이는 일반 사용자의 플레이 시간이나 난이도 이해도를 측정한 값이 아니다. 모바일은 Edge 에뮬레이션이며 실제 휴대전화 성능 측정은 하지 않았다.

## 렌더 부담과 검토 기록

동일한 저장·위상·입구 시점·1440×900 화면에서 후처리를 포함한 호출 수는 **634회 → 618회**, 삼각형은 **18,241개 → 22,717개**였다. 건축을 추가해 삼각형 수는 늘었지만 반복 석재를 묶어 호출 수를 줄였다. 기둥 장식의 색이 바뀌는 높이에만 꼭짓점을 두어, 중간 구현의 불필요한 40단 분할에서 측정된 27,197개 삼각형도 줄였다. 이 수치만으로 프레임 속도 향상을 주장하지 않는다.

검토 중 발견한 문제도 바로잡았다. 기둥의 색 띠를 넣을 때 엔진의 삼각형 나열 순서를 잘못 가정해 세로 무늬가 생겼고, 높이별 순서로 정리했다. 실패 복귀 위치를 저장 재개 위치와 같다고 가정한 검사는 실제 안전 구역 복귀 여부를 확인하도록 수정했다. 두 위치는 각각 `방 시작−1.4u`, `방 시작−1u`다.
