# 앱 전체 재구성·마무리 감사

목표: “끝까지 재구성해서 앱 마무리 ㄱㄱ 레퍼런스 게임 필요해요?”

불의 신전 완료와 앱 전체 완료를 구분한다. 이번 목표는 시작·탐험·여섯 신전·기록·귀환·엔딩·저장·함께하기를 연결된 제품으로 완성하는 것이다. 기존 사용자의 기록과 Blender·참고 원본은 보존한다. Three.js 웹판이 실행 기준이다.

**현재 결과:** 로컬 웹판의 기능 마감을 완료했다. 시작부터 여섯 신전의 현재 퍼즐, 기록·귀환·엔딩과 저장을 검사했고, 사용자 결정에 따라 함께하기를 **같은 교실 네트워크의 2~3명 균형 공동 실험**으로 연결했다. 모든 신전을 온라인 공동 모험으로 바꾼 범위는 아니다. GitHub 업로드·공개 사이트 신규 배포는 이번 작업에서 하지 않았다.

## 디자인 기준

레퍼런스를 새로 받아야 시작할 수 있는 상태는 아니다. 기존 시안과 아래 공식 자료를 기준으로 재구성한다.

- [젤다: 야생의 숨결 공식 소개](https://www.nintendo.com/en-gb/Games/Nintendo-Switch-games/The-Legend-of-Zelda-Breath-of-the-Wild-1173609.html): 탐험과 발견을 기준으로 삼는다. 우리 앱에는 ‘관찰 → 도구 조작 → 바뀐 공간으로 이동’ 원칙을 적용한다. 이는 이 프로젝트의 설계 판단이며 원작 기능의 동일 재현을 뜻하지 않는다.
- [Outer Wilds 개발사 소개](https://www.mobiusdigitalgames.com/outer-wilds.html): 환경 변화와 탐사용 도구로 비밀을 발견한다. 이 앱에서는 수첩이 발견·지혜·다음 단서를 이어 주도록 구성한다. 기록 UI의 크기·페이지 나눔은 우리 앱 대상과 화면에 맞춰 설계한다.
- 수첩: 기존 종이·입체 표지·페이지 넘김을 유지한다. 글자를 작게 해 한 화면에 밀어 넣지 않는다. 좁은 창에서는 내용이 여러 쪽으로 나뉘고 이전/다음·쪽 번호가 보이게 만든다. 숨긴 기록은 읽기 전까지 새 기록 반짝임을 소모하지 않는다.

## 바로잡은 원인

- 이전 공통 F는 상태 변화/분기가 있는 물·불 신전을 직선으로 통과하려는 오래된 전제였다. 실제 물 신전 입력 완주는 21개가 통과했다. 검사의 적용 대상과 전용 동선 검사를 구분해야 한다.
- 이전 공통 M은 읽기 쉽게 키운 글자와 ‘모든 기록 한 장’ 요구가 충돌한다. 글자를 유지하고 넘기는 방식으로 내용을 나눈다. 실제 모든 쪽과 기록 접근을 검사한다.
- 이전 공통 T는 소포가 아직 우주에 있는 최초 상태에서 엔딩 보내기를 검사한다. 완료된 탐험의 정상 범선 상태를 준비하고 저장을 복원하도록 검사 계약을 수정한다.
- `check-endflow.cjs`의 완료/중단 엔딩·새 게임 선택·백업 차단/손상 복원 15개는 현재 코드에서 통과했다. 이것만으로 실제 여섯 신전 완주를 증명했다고 보지 않는다.
- 지층 관문을 읽어 보니 힌트가 ‘드릴 날 쪽이 땅 위’라고 말하지만 실제 배치는 날 쪽에 가장 깊은 층을 두고 있었다. [USGS 시추 기술 자료](https://pubs.usgs.gov/twri/twri2-f1/pdf/twri_2-F1_b.pdf)의 날·코어 배치와 대조해 날 쪽이 깊은 끝이라는 설명으로 바로잡았다. 이전 판의 정답 순서·저장 배치는 바꾸지 않았다. 실제 모델의 양 방향 배치와 올바른 풀이가 일치하는지 검증했다.

## 이번 구현

### 기록을 읽는 수첩

확대한 한국어 글자를 유지하고 물음·들·부엌을 실제 내용 높이에 따라 여러 쪽으로 나눈다. 하단 이전/다음·쪽 번호, PageUp/PageDown, 터치 이동과 입체 넘김을 연결했다. 아직 펼치지 않은 기록의 ‘새 기록’ 반짝임은 읽기 전까지 유지한다. 자동 측정도 모든 쪽을 검사하며 개인 읽음 상태를 되돌려 놓는다.

검사 중 Edge가 GLB 요청을 HTTP 200 뒤 `ERR_ABORTED`로 표시해도 실제 모델이 디코드된 경우가 있었다. 무시 목록만 만들지 않고 해당 장면의 **실제 GLB 노드가 로드됐는지** 대조하게 수첩 검사 도구를 수정했다. 진짜 네트워크 오류·누락 모델은 계속 실패한다.

### 마지막 시간의 수호자

[목표 이미지·설계·실제 정면/측면/후면](../../art/chronicle-temple/v01/review.html)을 만든 뒤 Blender 수호자·좌대·왕좌를 웹에 연결했다. 후드의 별빛 얼굴, 청동 고리, 다섯 봉인이 있으며 바닥 0m·높이 14.038m·19개 메시·219,204삼각형이다. 봉인은 사당 ID에 연결하므로 헌납 순서가 달라도 같은 표지에 같은 색이 켜진다. 문양을 발광 면 앞으로 올려 대비를 확보했다.

비동기 로드와 예전 시각 저장을 함께 다뤄 구형 몸체가 겹치지 않게 했다. 144방향 실제 표면 충돌과 기본 시점의 발·머리·후광을 검사했다. 기존 코어·낙석·다섯 문·헌납·각성·마지막 구슬을 실제 입력으로 풀고 범선과 소포까지 이어 갔다. 이전 세 방이나 전당 주변 건축 전체를 상세 Blender 모델로 다시 만든 작업은 아니다.

### 교실에서 함께하기

사용자가 같은 교실 네트워크를 선택했다. **`교실서버.cmd`**를 더블클릭하면 게임과 방 API가 5514번으로 열리고 학생 접속 주소가 표시된다. [교실 운영 안내](../../server/README.md). 계정 없이 8자리 코드, 최대 3명, 서버가 상자 소유권·배치·문 열림을 판정한다. 제작용 5512번도 같은 API를 포함하지만 외부 접속은 받지 않는다.

공동 실험 중 개인 자동 저장과 구슬 보상을 차단한다. 완료·중도 퇴장 뒤 원래 범선/행성으로 돌아가고, 공동 대화가 개인 모험 대화를 소모하지 않게 했다. 범선에서 함께하기에 들어갈 때 개인 탐사 진행을 잘못 저장하던 경로도 제거했다. 연결 문제는 게임 알림과 설정에 표시한다.

실제 내부 주소 `http://192.168.55.247:5514/`로 독립 브라우저 3개가 참여해 모든 공동 실험, 문, 수호자까지 보행, 원래 범선 복귀와 개인 기록 격리를 통과했다. 이 주소는 이 PC의 현재 네트워크 값이며 다른 교실에서는 실행 창에 새로 표시되는 주소를 사용한다. 교실 서버는 런타임 파일만 제공하며 `.git`·환경 파일·제작 원본을 제공하지 않는다.

## 검증 근거와 한계

- 신규 근거는 [app-completion evidence](evidence/app-completion/)에 둔다. `strata-journey.json` 14개, `chronicle-art.json` 7개, `app-progress.json` 7개, `notebook-pages.json` 19개. `classroom-browser.json`에는 내부 접속 주소·독립 브라우저 수와 범위를 기록한다. [검증 색인](evidence/app-completion/verification-index.json)에 통과한 20개 결과 파일의 사본·작성 시각·해시, 주요 실행 소스와 GLB 해시를 남겼다. 기본 소스·저장·음향·상태·교실 서버의 실행 로그도 같은 폴더에 보존한다.
- 새 검사의 실제 검출 확인: `--break-core-tip`은 드릴 끝 불일치, `--break-seals`는 봉인 ID 연결 오류, `--break-next`는 수첩 다음 쪽 버튼 고장을 각각 검출해 예상대로 exit 1이다. 정상 결과 파일과 구분한다.
- [여덟 장면 실제 웹 검수](../../art/app-completion/review.html)는 중간 화질·1280×800 입구 캡처다. 위치를 준비한 화면이며 퍼즐 완주 증거와 구분한다. 렌더 호출·삼각형을 실제 학생 기기 FPS로 해석하지 않는다.
- 여러 신전은 전용 검사가 각각 시작 상태를 준비해 실제 조작으로 푼 것이다. 하나의 세션을 쉬지 않고 처음부터 끝까지 플레이한 학생 관찰 기록은 아니다. 같은 저장에 여섯 신전의 진행과 운반 상태를 넣고 새로고침·모드 전환을 별도로 검사했다.
- 학생들의 첫 플레이 재미·이해도·실제 태블릿 속도와 학교 와이파이의 기기 간 접속 허용은 현장에서 확인할 항목이다. 이번 교실 검사는 같은 PC의 독립 브라우저 3개로 내부 주소를 사용했으며 서로 다른 학생 기기 3대의 실험은 아니다.
- 목표 시안의 미세 조각·균열·천 질감과 전체 전당 장식까지 일치하지 않는다. 기존 자산을 보존하며 현재 기능과 시각적 개선 범위를 명확히 했다.

기능 마감 이후의 우선순위는 실제 교실에서 해법 설명 없이 2~3명이 플레이하며 이해도·기기 성능을 관찰하는 것이다. 이는 완료된 로컬 기능 검사와 구분되는 현장 검토다.
