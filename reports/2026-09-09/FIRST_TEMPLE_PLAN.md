# 첫 신전 개편 계획 — 별의 천칭 회랑

상태: 계획안. 이번 단계에서는 게임 코드와 Blender 모델을 변경하지 않는다.

## 1. 항해대 숫자 가독성부터 해결

현재 `src/world/Lab.js`의 숫자판은 손잡이와 같은 중심에 있고 손잡이가 숫자 앞에서 회전한다. 숫자판 아래쪽은 상판 높이와 겹친다. 단순히 글꼴을 키우면 해결되지 않는다.

제안은 **상판 위로 솟은 세 개의 고정 숫자창 + 각 창 아래의 독립된 회전 손잡이**다. 숫자창을 항해대 안에 자연스럽게 통합하되 전면으로 조금 내밀어 책상과 겹치지 않게 한다. 황동 테두리, 어두운 바탕, 밝은 큰 숫자로 구성하고 표시창은 회전시키지 않는다. 조작 중인 창만 테두리로 강조한다.

- 숫자창 위치·크기는 실제 캐릭터 시점으로 결정한다. 정면뿐 아니라 좌우 비스듬한 시점에서도 읽혀야 한다.
- 세 숫자는 상판·손잡이·계기판에 가리지 않아야 한다. 접근 시 필요하면 세 숫자를 작은 조작 안내에도 함께 보여 준다.
- 정답·E 조작·저장 형식·빛 연출은 유지한다. 숫자가 바뀌면 해당 창이 짧게 반응하며 동작 줄이기 설정도 따른다.
- 검증: 0~9 전체, 좌·중·우 접근, PC·모바일 세로/가로, 저장 복원, 항로 열림과 빛 연결.

## 2. 첫 방의 미술 방향

두 번째 사진은 `balance/r1`, 이름은 ‘무게 순서’다. 현재 방은 폭 12, 길이 14, 높이 5.5이며 상자 다섯을 저울로 비교해 가벼운 순서대로 받침에 놓는다. 첫 관문의 학습 규칙을 유지하고 공간과 장치의 표현을 개편한다.

**별의 천칭 회랑: 우주를 여행하던 사람이 고대의 거대한 측정 장치 안으로 들어서는 첫 순간.**

입구 아치 너머 중앙 천칭, 후면의 다섯 받침, 가장 멀리 출구의 빛이 한눈에 이어지게 한다. 높은 아치와 층을 이룬 벽은 장엄함을 만들고, 장치 주변 바닥은 정돈해 손으로 조작할 공간을 확보한다. 전부 빛나게 하지 않고 저울·받침·출구에 시선을 모은다.

| 요소 | 제작 방향 | 플레이 역할 |
|---|---|---|
| 입구 | 깊은 문틀, 양쪽 천칭 부조, 황동 문양 | 신전에 들어서는 첫 장면 |
| 건축 | 상아빛 석재, 짙은 청록 홈, 황동 이음, 높은 반복 아치 | 단조로운 직선 통로 개선 |
| 중앙 천칭 | 조각된 받침, 원형 축, 황동 가로대, 매달린 두 접시 | 무거운 쪽이 내려가는 결과를 크게 표현 |
| 실험 상자 | 운반 손잡이와 서로 다른 식별 문양 | 크기·색이 무게 정답을 누설하지 않게 구성 |
| 다섯 받침 | 얕은 원형 제단, 순서 표식, 물건 놓는 면 | 가벼운 것부터 놓는 순서를 명확히 표시 |
| 바닥 | 중앙 측정 문양과 가장자리 석재 띠 | 경로를 안내하되 장치와 혼동하지 않게 함 |
| 목표·힌트 | 큰 검은 팻말을 낮은 석제 안내대로 교체 | 짧은 제목과 핵심 문장, 상세 내용은 읽기 화면 |
| 출구 | 이중 문틀, 분리되어 열리는 석문, 청록빛 틈 | 성공 후 다음 공간으로 자연스럽게 안내 |
| 조명 | 위에서 들어오는 따뜻한 빛, 장치의 청록빛, 소량의 먼지 | 형태와 깊이 강조, 숫자와 문장은 번짐 방지 |

기본 동선은 **입구 → 상자 선택 → 중앙 저울 비교 → 뒤쪽 받침 배치 → 출구**다. 저울 양쪽으로 돌아갈 통로를 두고, 상자를 내려놓아도 입구와 출구가 막히지 않게 한다. 중앙 장치는 극적으로 보이되 카메라와 시야를 가릴 정도로 키우지 않는다.

## 3. Blender 제작과 코드 분리

범선에 사용한 Blender 포터블을 활용한다. 먼저 회색 단순 모델로 실제 보행·접근·카메라를 확인한 뒤 조각과 재질을 올린다.

- 정적 건축: 바닥, 기둥, 아치, 벽, 부조, 문틀. 반복 부품은 재사용한다.
- 가동 부품: 저울 축·가로대·두 접시, 받침, 문짝을 독립 객체로 내보낸다. 축과 원점을 실제 회전 지점에 둔다.
- 코드: 무작위 무게, 비교 판정, 집기·놓기, 순서 판정, 저장 복원은 `WeighGate.js`와 `DeviceProgress.js` 계약을 유지한다.
- 예정 구조: `tools/blender/build_balance_court.py`, `art/balance-court/balance-court-v01.blend`, `assets/models/balance-court-v01.glb`, 배치 데이터 `src/data/balanceCourt.js`, 표현 계층 `src/shrine/BalanceCourt.js`.
- 기존 공통 방의 바닥·팻말·장식이 새 모델과 겹치지 않도록 `Room.js`에 명시적인 교체 지점을 둔다. 다른 사당의 장면은 함께 바꾸지 않는다.
- 시각 모델과 충돌은 분리한다. 가는 사슬과 장식은 카메라를 밀지 않고, 벽과 주요 장치는 실제 보행 경계와 맞춘다.

초기 제작 목표는 방 전용 모델 삼각형 8만 개 이내, 재질 12개 이내, 텍스처 최대 2K다. 이는 측정 전 목표이며 전체 프레임 비용을 뜻하지 않는다. 가장 낮은 화질에서는 먼지·빛 기둥 등 장식을 줄이고 퍼즐 표식과 저울 움직임은 유지한다.

## 4. 연출 시나리오

1. 입장: 깊은 문틀 너머 천칭을 보여 준다. 조작을 길게 막는 강제 카메라는 피한다.
2. 첫 비교: 접시가 천천히 내려가고 가로대와 중앙 바늘이 같은 결과를 보여 준다. 무게 수치 대신 상대적인 무거움만 알려 준다.
3. 배치: 상자가 받침에 안착한다. 빛은 ‘놓였다’는 반응이며 정답 여부를 미리 알려 주는 용도로 쓰지 않는다.
4. 성공: 기존 성공 판정 이후 다섯 받침의 빛이 출구로 이어지고 문이 열린다. 반복 방문에서는 긴 연출을 생략한다.

장식 때문에 학습 규칙이 달라지지 않도록, 실험 상자의 재질·문양은 무게와 독립적으로 배정한다. 비교 전에는 큰 상자가 무거울 것이라고 단정할 수 없어야 한다.

## 5. 구현 순서와 완료 기준

| 단계 | 산출물 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 1 | 항해대 숫자창 개선 | 실제 접근 시점에서 세 숫자 판독 가능 |
| 2 | 입구 시점·저울 근접·평면 배치 레퍼런스 | 같은 방의 형태·색·장치 배치가 일치 |
| 3 | Blender 단순 공간 모델 | 상자 운반, 저울 양쪽 접근, 카메라 회전 가능 |
| 4 | 건축·장치 상세 모델과 재질 | 원본 `.blend`와 게임용 GLB, 축·이름 검증 |
| 5 | 기존 퍼즐에 새 시각 표현 연결 | 무게·배치·집기·놓기·저장 진행 보존 |
| 6 | 조명·성공 연출·성능 조정 | PC·모바일에서 표식 가독성과 조작 확인 |

최종 검증은 무작위 배치 여러 판의 해결 가능성, 잘못 놓기·다시 들기, 든 상태 및 저울·받침 배치 저장 복원, 성공·재방문, 다음 방 이동, 카메라 끼임, 모바일 조작, 화질별 프레임 비용을 포함한다. 자동 검사 통과 외에 처음 하는 사람의 연속 플레이로 목표와 동선이 이해되는지도 확인한다.

이번 범위는 **항해대 숫자 가독성 + 균형의 사당 첫 관문**이다. 두 번째 압력판 방과 마지막 균형 신전은 첫 방의 완성된 부품·재질 규칙을 바탕으로 이후 확장한다.

바로 다음 작업: 숫자 표시 구조를 먼저 개선하고, ‘별의 천칭 회랑’ 레퍼런스 세 장을 만든 뒤 Blender 공간 모델 제작으로 이어간다.
