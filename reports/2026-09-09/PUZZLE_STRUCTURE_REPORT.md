# 기존 퍼즐 구성 분석 보고서

2026-09-09 · 현재 로컬 소스 기준 정적 분석. 이번 보고서를 위해 게임 규칙을 변경하거나 새로운 플레이 검사를 실행하지 않았다. 사진에 나온 균형의 사당 첫 방을 집중 분석하고 전체 게임에서의 위치를 함께 정리했다.

## 핵심 판단

이 게임은 **탐험 → 장치 관찰 → 직접 조작 → 결과 비교 → 통과 → 수첩 기록**을 반복하는 과학 탐험 게임이다. 사진의 첫 방은 물건의 무게를 눈으로 추측하는 대신 저울로 비교해 순서를 만드는 퍼즐이다. 디자인 개편의 중심은 이 비교 행동이 더 잘 보이도록 만드는 것이다.

## 전체 게임의 흐름

우주 범선에서 소포를 회수하고 수첩을 읽는다. 항해 고리를 맞춰 행성으로 출발하고, 행성을 걸어 사당을 발견한다. 사당 안에서는 앞 관문을 해결해야 다음 방의 문이 열린다. 마지막 장치를 해결하면 구슬이 나타나고, 실제로 획득하면 해당 사당의 완료가 기록된다. 여섯 사당 완료 후 귀환과 다음 여행자에게 기록을 전하는 엔딩으로 이어진다. 야외 채집·요리·탐험 기록도 병행한다.

| 사당 | 일반 관문 구성 | 중심 행동 |
|---|---|---|
| 균형 | 무게 순서 → 무게 압력판 | 비교 → 합 만들기 → 마지막 지레 균형 |
| 그림자 | 그림자 밟기 → 거울 세 장 → 그림자 크기 | 그늘 이동, 반사 방향, 투영 크기 조절 |
| 체 | 체 고르기 → 성질로 나누기 → 거름과 증발 | 도구 선택, 성질 비교, 처리 순서 |
| 세 모습 | 얼려서 건너기 → 미끄러운 바닥 → 세 모습의 회랑 | 상태 변화와 이동·장치 연결 |
| 흔들리는 | 흔들림 장치 → 용암 육각형 → 간헐천 | 관찰, 회피, 타이밍 |
| 시간 | 층의 순서 → 내려가는 갱도 → 다섯 색의 문 | 순서 배치, 이동, 표식 해석 |

총 일반 관문은 17개, 마지막 퍼즐은 6개다. 균형만 일반 관문 2개이고 나머지는 각각 3개다. 사당 목록에서 첫 번째인 균형의 사당이 모든 플레이어의 첫 방문으로 강제되는 것은 아니다. 따라서 첫 방은 사전 지식 없이도 이해 가능해야 한다.

## 균형 사당의 세 단계

1. **무게 순서:** 수치를 숨긴 다섯 상자를 비교하고 가벼운 순서대로 놓는다.
2. **무게 압력판:** 표시된 무게를 가진 상자를 두 판에 나눠 올려 각각의 목표 합을 만든다. 주문 세 라운드를 해결한다. 주문은 보유 상자를 양쪽에 배분해 해결 가능한 조합에서 고른다.
3. **마지막 균형 장치:** 무게뿐 아니라 중심에서의 거리도 고려한다. 왼쪽 고정 추는 3kg×2칸이고 양쪽의 ‘무게×칸수’ 합이 같으면 성공한다. 예를 들어 오른쪽 2kg을 3칸에 놓으면 같은 6이 된다. 실제 배치 가능한 추·빈 칸을 확인하며 조합한다.

첫 방과 마지막 신전은 서로 다른 퍼즐이다. 첫 방의 저울은 양팔 길이가 같고 상자를 정렬하는 도구이며, 마지막은 위치별 거리 자체가 정답 조건에 들어가는 지레다.

## 첫 방: 실제 플레이와 판정

| 구성물 | 현재 구현 |
|---|---|
| 공간 | 폭 12 × 길이 14 × 높이 5.5, 균형 사당 `r1` |
| 상자 | 내부 무게 1·2·3·4·5, 각 한 개. 무게 숫자를 직접 표시하지 않음 |
| 크기 | 0.50~1.06의 다섯 크기. 크기 순위와 무게 순위가 최소 세 자리에서 다르도록 섞음 |
| 초기 위치 | 입구 쪽 다섯 위치에 무작위 배치 |
| 비교 장치 | 접시 두 개, 한 접시에 상자 하나 |
| 답안 받침 | 뒤쪽 다섯 개. 왼쪽부터 1~5개의 점으로 순서 표시 |
| 조작 | E로 집기, 접시에 올리기, 받침에 놓기, 다시 들기 |

플레이어는 상자를 하나씩 두 접시에 올린다. 무거운 쪽이 내려가고, 양쪽 모두 상자가 있을 때 ‘왼쪽/오른쪽이 무겁다’는 문장이 나온다. 비교한 상자를 다시 집어 다른 상자와 비교하고, 가벼운 것부터 왼쪽 받침에 배치한다.

정답 판정은 다섯 받침 모두가 채워지고, 각 받침의 상자 무게가 차례로 **1, 2, 3, 4, 5**인지 확인한다. 일부만 맞혔다고 해당 받침만 정답 색으로 알려 주지는 않는다. 모두 맞으면 받침이 금빛으로 바뀌고 방의 문이 열린다. 틀린 배치는 상자를 다시 들어 고칠 수 있다. 이 장치 자체에는 제한 시간이나 생명 감소가 없다.

한 가지 풀이 방법은 먼저 가장 가벼운 상자를 찾고 첫 받침에 놓은 뒤, 나머지에서 다시 가장 가벼운 것을 찾는 것이다. 이는 가능한 전략의 예이며 게임이 특정 비교 순서를 강제하지는 않는다.

## 코드와 저장은 어떻게 연결되는가

- [layouts.js](../../src/shrine/layouts.js): 방의 크기·순서·목표·힌트와 장치 종류를 선언한다.
- [Room.js](../../src/shrine/Room.js): 방과 문, 장치, 안내를 조립한다.
- [WeighGate.js](../../src/shrine/WeighGate.js): 상자·저울·받침 생성, 가까운 대상 선택, E 조작, 기울기와 정답 판정을 담당한다.
- [boot.js](../../src/boot.js): 장치를 갱신하고 성공하면 문을 연다. 마지막 퍼즐 성공 후 구슬 획득도 연결한다.
- [DeviceProgress.js](../../src/shrine/DeviceProgress.js): 든 상자, 접시·받침의 상자, 위치 분류, 기울기와 성공 상태를 저장·검증한다. 한 상자가 여러 위치를 동시에 차지하는 모순은 거부한다.
- [ShrineProgress.js](../../src/shrine/ShrineProgress.js): 사당의 생성 시드·진행과 장치 기록을 묶어 복원한다.

따라서 Blender 모델은 장치의 **외형과 움직이는 부품**을 공급하고, 정답과 저장은 기존 코드가 담당하는 구성이 적합하다.

## 발견한 문제와 개선 제안

아래는 확인된 동작과 앞으로의 제안이다. 아직 수정하지 않았다.

| 확인된 현재 동작 | 영향 | 제안 |
|---|---|---|
| 상자 목재색을 `woods[w-1]`로 선택 | 반복 플레이 시 색으로 무게를 외울 가능성 | 외관·식별 문양과 무게 연결을 매 판 독립적으로 섞고 저장 |
| ‘여기 내려놓기’를 누르면 `home`으로 돌아감 | 안내와 실제 위치가 불일치 | 우선 ‘원래 자리에 돌려놓기’로 명확히 안내. 자유 배치는 충돌·저장까지 별도 설계 |
| 저울 각도가 무게 차에 비례하고 일정 크기에서 제한됨 | 방향 외에 기울기 크기도 차이의 단서가 됨 | ‘어느 쪽만 알려 주기’가 목표라면 기울기 크기를 일정하게 통일할지 결정 |
| 1~5가 한 개씩이므로 서로 다른 두 상자의 무게는 같지 않음 | 코드의 ‘같다’ 문구는 정상 두 상자 비교에서 사실상 나오지 않음 | 동등 비교를 학습 목표에 넣으려면 중복 무게와 정답 판정을 함께 재설계 |
| 크기 순위는 최소 세 자리 불일치이며 완전 역순은 아님 | ‘큰 상자는 항상 가볍다’도 사실이 아님 | 안내는 ‘크기만으로 무게를 알 수 없다’로 유지 |
| 큰 검은 안내판과 단순한 저울·상자 | 장치보다 설명판이 화면을 지배 | 낮은 석제 안내대와 상세 읽기 화면, 중앙 천칭의 형태 강화 |

## 디자인을 바꿀 때 지킬 규칙

상자는 다섯 개, 저울은 하나와 접시 두 개, 답안 받침은 다섯 개로 유지한다. 상자 문양은 구별을 돕되 무게 순위를 표시하지 않는다. 받침의 점은 순서 표시이며 상자 무게 표시와 혼동하지 않게 한다. 접시·받침에 접근하는 경로와 다시 집는 조작을 항상 확보한다.

먼저 [신전 상세 레퍼런스와 제작 기준](BALANCE_COURT_REFERENCE.md)을 기준으로 공간을 검토하고, 이후 Blender 단순 모델 → 실제 보행 확인 → 상세 모델 → 퍼즐 연결 순으로 진행한다. 이번 산출물은 분석과 디자인 기준이며 게임 적용 완료를 뜻하지 않는다.
