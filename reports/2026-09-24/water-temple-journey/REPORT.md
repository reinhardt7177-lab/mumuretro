# 물의 신전: 세 방 연결과 로컬 저장

## 실행

`unity/MumuPlanet/Builds/WaterTempleJourney/WaterTempleJourney.exe`

얼음길 → 구름 집수실 → 순환의 성소 순서다. 각 방의 출구를 실제로 통과하면 다음 장면으로 이동한다. 팔찌는 첫 방에서 한 번 얻으며 이후에도 유지된다. 마지막 출구를 통과하면 세 방 탐사 완료 상태로 남는다.

## 저장되는 내용

- 현재 방, 팔찌 획득, 최종 방 통과 여부
- 각 장치의 얼음·물·수증기 양과 집수판 냉각 상태
- 영구 복귀 다리, 출구 수문, 집수실 다리와 상층 방문 여부
- 집수판 가로 위치, 순환실 물길 전환 및 상층 밸브

변경이 있을 때 최대 1초 간격으로 저장한다. 창 포커스 상실·일시정지·정상 종료에도 저장한다. 방 전환 직전에 다음 방을 기록한다. 강제 종료나 전원 차단 직전 최대 1초의 변경은 반영되지 않을 수 있다.

재시작하면 해당 방의 안전한 시작 발판/방문한 회랑에서 이어진다. 공중 위치, 집수판을 잡는 동작, 누른 채 사용하던 능력은 복원하지 않는다. 물의 상태는 유지된다.

Unity의 `Application.persistentDataPath` 아래 `water-interior-journey-v1.json`을 사용한다. 임시 파일을 작성한 다음 교체하고 이전 파일은 `.bak`으로 남긴다. 기존 무게 신전·행성·웹 저장은 건드리지 않는다. 손상·미지원 버전·장치 구성 불일치 기록은 덮어쓰지 않고 안내를 표시한다. 이 경우 해당 세션은 진행 가능하지만 저장을 보장하지 않는다.

## 구현 범위

세 방을 연결한 별도의 Windows 기능 시제품이다. 행성의 실제 물의 신전 입구, 신과의 대화·보상·자동 탈출·밀봉, 최종 Blender 아트와 온라인 협동은 이번 단계에 포함되지 않는다. 완료 후 다시 시작하는 별도 메뉴도 아직 없다.

## 제작 및 검증

- 빌드: Unity 메뉴 `Mumu / Build connected water temple`
- 검사: `unity/check-water-journey.ps1`
- 기존 개별 시험 장면을 바탕으로 `WaterJourneyIce`, `WaterJourneyCollection`, `WaterJourneyCycle`을 생성한다. 기존 메인 캠페인 빌드 목록은 변경하지 않는다.
- 저장 검사는 별도 파일과 다섯 번의 독립 프로세스를 사용한다. 장면 전환, 부분 상태 복원, 완료 재개, 손상 기록 보존을 확인한다.
- 검사에서 일부 퍼즐 상태 및 캐릭터 위치를 직접 준비한다. 전체 구간의 수동 키보드 플레이나 학생 체험 평가를 대신하지 않는다.

검증 결과는 빌드/실행 후 아래에 기록한다.

## 검증 결과

- Unity 6000.0.84f1 Windows 빌드 성공, 에디터 종료 코드 0.
- 다섯 번 독립 실행: 새 저장 11개, 얼음길 재개/전환 6개, 집수실 재개/전환 7개, 순환실 재개/완료 5개, 완료 기록 재개 3개. 총 **32개 검사 통과**, 모두 종료 코드 0.
- 손상 JSON·빈 객체·미지원 버전·잘못된 방 번호 원본 보존, NaN 및 물 총량 불일치 거부 확인.
- 최초 검사에서 Unity의 null 배열 → 빈 배열 직렬화 경계를 발견해 수정했고, 해당 왕복 직렬화 회귀 검사도 포함했다.
- 실제 장면 로딩 및 프로세스 재시작을 사용했다. 퍼즐 준비/완료 검사의 일부는 상태와 위치를 직접 설정하므로 전체 수동 플레이 테스트는 아니다.
- 외부 Unity 분석 서버 연결 오류는 제한된 네트워크에서 발생했다. 게임 예외나 컴파일 오류와 구분한다. 온라인 기능은 이번 검사 대상이 아니다.
