37개 검사는 승강대와 승객의 컨트롤러 업데이트 전/후 발 높이, 실제 운행 중 새로고침, v1 원문·사본 보관과 저장 실패, 모순된 기록 거부, 상층 36개 카메라 시점, 높이에 맞는 황금 가루, 터치 E·수첩과 세 화면 크기를 포함한다. 결과는 `reports/2026-10-21/evidence/fire-steam/report.json`의 `pass: true`로 확인한다. 기존 두 도구는 각 33개를 계속 실행한다. 기능 검사와 학생 재미·실제 기기 성능은 별개다.

`--break-rider-transport`는 테스트 브라우저에서 승강대가 승객에게 전달한 이동량만 되돌린다. 기존 컨트롤러가 나중에 바닥 높이를 보정하기 **전** 발 높이 오차를 검출해 종료 코드 1이 나와야 한다. 정상 코드·사용자 기록은 바꾸지 않으며 `failure-injection.json`에 근거가 남는다.

## 작업대 시야 · 2026-10-26

범위는 균형·분리 첫 작업장과 입구다. [설계/83장 비교](../art/workspace-camera/v01/review.html), [검증과 한계](../reports/2026-10-26/WORKSPACE_CAMERA.md)를 함께 읽는다. 기존5512 서버와 `AUDIT_NODE_MODULES`의 Playwright를 사용하며 실제 개인 브라우저 저장을 사용하지 않는다. Windows의 검증 프로세스에만 다음 임시 경로를 지정한다. 전역 환경이나 자동 정리를 바꾸지 않는다.

```powershell
$env:TEMP = 'D:\mumumetro\tmp\browser-validation'
$env:TMP = $env:TEMP
node tools/probe-workspace-camera.cjs after
node tools/probe-workspace-camera.cjs after --portrait
node tools/probe-workspace-camera.cjs after --landscape
node tools/check-workspace-camera-views.cjs after
node tools/check-workspace-camera-views.cjs after-portrait
node tools/check-workspace-camera-views.cjs after-landscape
node tools/check-workspace-camera-controls.cjs
```

구도 검사는 입구만 준비하고 실제 컨트롤러 입력으로 접근한다. 검사기가 경로를 알고 `camYaw`를 조향하며, 걸어가는 도중 발 좌표를 직접 바꾸지 않는다. 본편 입력 검사와 구분한다. 장치 GPU 마스크·근거리 점유와 별도로 장치 경계8점/몸9표본을 확인한다. 옆/뒤에서 장치가 화면 밖인 값은 측정 불가다. 세로·가로는 실제 터치 컨텍스트다.

`run-workspace-camera-case.cjs input|balance|sift|shadow|coop`는 기존 검사의 조건을 유지하고 출력만 이번 근거 폴더로 격리한다. `input`은 실제 키보드/마우스/터치·운반·점프/놓기다. `balance`는 범선부터 실제 보행으로 진행하고, `sift`는 범선/착륙 후 신전 입구를 준비해 이후 연속 진행한다. `coop`는 교사 PC 서버 방식의3브라우저 공유 명령·문 통과 보행·개인 저장 분리이며 실제 학생 기기 시험이 아니다. `shadow`의 모델 대체 검사에서는 실제 GLB 요청이 차단됐는지도 센다.

고장 주입은 브라우저의 소스 응답 또는 검사 컨텍스트만 바꾸며 작업 트리/개인 저장을 수정하지 않는다.

```powershell
node tools/probe-workspace-camera.cjs after --fault=workspace
node tools/check-workspace-camera-views.cjs after-fault-workspace
node tools/probe-workspace-camera.cjs after --fault=follow
node tools/check-workspace-camera-views.cjs after-fault-follow
node tools/check-workspace-camera-controls.cjs --fault=late
```

두 `probe`는 고장 상태의 동선을 완주해 종료0이 될 수 있다. 뒤의 구도 판정은 의도한 가림/급이동으로 **종료1**이 나와야 한다. `--fault=late`는 현재 방에 다른 방 기둥이 들어가고 발 위치가 바뀌는 진단으로 종료1이어야 한다. 브라우저 예외·준비 실패를 검출 성공으로 세지 않는다.

`measure-workspace-camera.cjs`는 다른 캡처/Blender 작업이 끝난 뒤 단독 실행한다. 변경 전/후·두 방·정지/이동8경우에서30준비/120RAF를 기록한다. 목표 입력이 같아도 카메라/일부 발 경로는 달라져 FPS 향상의 인과 증명이 아니다. CPU step·제출·RAF·렌더 호출·JS 힙과 GPU 바이트를 구분한다.

`review-workspace-camera.cjs`는 비교/도면을, `archive-workspace-camera.cjs`는121항목·고장3종·30목표/제품 일치·이미지 링크·447기존파일/222자산/453빌드를 대조한다. 교실 결과는 모든 단언 후 기록되는5개 시나리오 문자열이며, 수집기는 별도의 참가/대기 근거도 확인한다. 기본 소스·저장·오디오 검사는 계속 별도로 실행한다.

`before`/`goal`은 보존한 기준/시제품 응답이다. 기존 `baseline.json`을 덮어쓰지 않는다. `install-workspace-camera.cjs`는 검사가 아니라 검증한6파일을 복사하는 도구이며, 현재 해시가 기준 또는 직전 설치와 같을 때만 실행한다. 일반 검증에서 반복 실행하지 않는다. Blender 원본과 현재 자산을 삭제하지 않는다.
